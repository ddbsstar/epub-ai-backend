# 上传、选章、转换：产品主流程

日期：2026-10-23。

用户明确的构想是：上传 EPUB，列出全部章节，勾选后点击转换，将生成的图片插入书中。本文保留产品设计依据；其后用户要求补齐实现，现已完成[本机多章节转换版本](chapter-illustration-conversion.md)，具体限制与验证范围以该文为准。

## 用户明确的流程

1. 上传一本 EPUB。
2. 展示书中的全部真实章节。
3. 勾选需要插画的章节。
4. 点击“开始转换”，后台理解选中章节、生成插画、插入对应位置。
5. 下载包含这些插画的同一本 EPUB。

用户不需要手动输入章节序号，不需要为每章分别点击“规划”和“生图”，不需要下载多本单章文件后自行合并。后台仍保留分析、规划、生成、组装、校验的内部步骤。

## 配套交互建议

以下是为落实上述流程提出的细节，不代表用户已决定所有默认项。

- 沿用现有上传页，不新增必经页面。上传后左侧显示目录勾选区，右侧保留封面、转换与最终下载，底部保留总进度。
- 上传和目录解析不调用付费模型。去掉当前前端上传成功后自动创建普通排版任务的串联，选章之前不开始 AI 整理。
- 初始不自动勾选；提供全选、取消全选及“已选 N 章”。只对选中且受支持的章节调用模型。需要在原目录顺序中显示章节，不按 XHTML 文件数冒充章节数。
- 目录可保留层级。封面、版权页、目录等非章节项目区分展示；不能可靠索引的条目显示原因并禁选，不能从列表中无提示消失，也不能截取前若干章后声称目录完整。
- 首个批量版本默认每个选中章节一张图，放在本章末尾，所有图使用同一个明确的风格配置。暂不叠加每章多图、章中位置选择等额外控制。
- 点击前显示章节数量、图片数量与保守费用估计/预算。超过限额时在提交前阻止并提示缩小选择或调整允许的预算，不能先收下全部章节再悄悄只做一部分。
- 运行时逐章显示等待、理解内容、生成插画、已就绪、跳过或失败；同时显示整体已处理章节数和成功图片数。打包与格式校验另显示真实阶段，不伪造百分比。
- 某章失败可保留原因并继续其他章节；最终有成功图时导出包含成功图的整本书，并明确标成“部分完成：成功 X、失败 Y、跳过 Z”。一张也未生成时不能显示“插画转换完成”。
- 图片预览可在任务过程中逐张出现；不把人工逐章确认作为默认必经步骤。修改、替换或重新生图属于之后的显式版本操作，不允许后台因为美感判断自动无限重画。
- 刷新恢复查询，不重新生成；成功图复用。已发送且结果未知的调用保留费用预占，不因用户点重试或新建任务再次提交同一付费请求。

## 后端实施边界

### 免费目录

将 `chapter-illustration-index.ts` 中已有的 OPF/spine/NCX/nav 解析提取成可复用目录索引，绑定 source hash 和解析器版本；免费接口仅返回安全的章节 ID、标题、顺序、层级及支持状态，不返回正文或私有文件路径。受 owner 与本机业务访问限制，但不依赖模型开关或生图凭据。

只解包并建立一次目录，不对每章重复调用现有全书解包的单章检查函数。待选中后，再按索引提取完整章节范围及验证安全锚点。章节标题/导航冲突时保留未支持状态，不猜测。

### 单个批次与逐章单元

转换请求冻结 owner、不可变 source hash、目录版本、已选择章节 ID、有界风格配置及预算。服务器验证这些章节均来自同一目录，去重并按原书阅读顺序执行；客户端不能传文件路径、任意模型地址或无限预算。

顶层维持少数粗阶段，章节是独立持久工作单元。现有 Run 最多 16 个唯一 stage，不能给每章创建一个 stage，也不能把全书正文、图片或无限子项塞进 Run JSON。单元需要结果引用、付费调用指纹、状态、租约及可复用检查点。

创建批次和重复点击按 owner/source/冻结选择与版本去重；明确修改选择或构图才是新版本，成功的相同请求资产仍可复用。预算必须约束整个批次，不能每开一个子 Run 就清零。先以受控并发执行，不在一个请求或数据库事务中等待所有章节生图。沿用 UNKNOWN 保守恢复，不能承诺上游恰好扣费一次。

### 一次组装多图

当前 `insertEpubIllustration()` 仅接受一个 anchor/image/alt。不能将上一份单章导出继续传入：原锚点与源 hash/偏移已变化，固定生成 CSS 资源也会发生冲突。

新增多插入计划：从一次不可变原书构建，验证全部锚点/资产绑定，按文档分组并以源码偏移逆序应用零长度补丁；CSS 只登记一次，每张图片使用唯一受控资源名和 manifest ID。所有选中章的成功图片最后只打包一次、执行一次最终 EPUBCheck，然后原子发布同一本 EPUB。

完整性验证必须从原始 body 与全部登记插入片段独立重建 expected body；未插图的章节正文继续一致。角色 CSS 若保留，必须依据全部插入重映射。报告列出每章采用、跳过和失败结果，不把部分成功写成全部完成。

## 实施验收

- 上传至目录阶段零模型调用；没有生图 Key 仍能查看目录。
- 合成书覆盖跨文件章、一文件多章、目录层级、非章节条目和歧义条目。
- 勾选两章只处理两章，两张图出现在同一 EPUB 的对应章末；未选章没有模型调用或插图。
- 重复点击、刷新和失去响应不会新增相同付费调用；取消、预算竞争和 UNKNOWN 不绕过已冻结范围。
- 一章失败另一章成功可得标明部分完成的统一产物；失败不会覆盖成功资产，全部失败不假装成功。
- 多图插入完整性、包内引用、原资源、格式校验与真实网页操作均分别验证。美感与阅读器实际显示另行验收。

本文最初只定义设计。当前本机实现及 HTTP DTO 已记录在[多章节转换](chapter-illustration-conversion.md)；正式数据库批量调度、生产部署与本文更完整的长期能力仍未全部实现。
